package com.example;

public class TrainTicketingSystem {

    // Method to calculate ticket price based on distance and class type
    public double calculateFare(double distanceInKm, String classType) {
        double baseRate;

        switch (classType.toLowerCase()) {
            case "first":
                baseRate = 1.5;
                break;
            case "second":
                baseRate = 1.0;
                break;
            case "sleeper":
                baseRate = 0.75;
                break;
            default:
                System.out.println("Invalid class type.");
                return -1;
        }

        if (distanceInKm < 0) {
            System.out.println("Invalid distance.");
            return -1;
        }

        return distanceInKm * baseRate;
    }

    // Method to check ticket availability
    public boolean checkAvailability(int availableSeats) {
        return availableSeats > 0;
    }

    // Method to book a ticket
    public String bookTicket(String passengerName, double distance, String classType, int availableSeats) {
        if (!checkAvailability(availableSeats)) {
            return "No seats available.";
        }

        double fare = calculateFare(distance, classType);
        if (fare < 0) {
            return "Ticket booking failed due to invalid input.";
        }

        return "Ticket booked for " + passengerName + " in " + classType + " class. Fare: $" + fare;
    }

    // Main method for testing
    public static void main(String[] args) {
        TrainTicketingSystem system = new TrainTicketingSystem();

        System.out.println(system.bookTicket("Alice", 120, "First", 5));
        System.out.println(system.bookTicket("Bob", 80, "Sleeper", 0));
    }
}

package com.example;

import static org.junit.jupiter.api.Assertions.*;
import org.junit.jupiter.api.Test;

public class TrainTicketingSystemTest {

    TrainTicketingSystem system = new TrainTicketingSystem();

    @Test
    public void testCalculateFare() {
        assertEquals(180.0, system.calculateFare(120, "First"), 0.001, "First class fare incorrect");
        assertEquals(60.0, system.calculateFare(80, "Sleeper"), 0.001, "Sleeper class fare incorrect");
        assertEquals(-1.0, system.calculateFare(80, "Luxury"), 0.001, "Invalid class should return -1");
        assertEquals(-1.0, system.calculateFare(-10, "First"), 0.001, "Negative distance should return -1");
    }

    @Test
    public void testCheckAvailability() {
        assertTrue(system.checkAvailability(5), "Should be available");
        assertFalse(system.checkAvailability(0), "Should not be available");
    }

    @Test
    public void testBookTicket() {
        String result1 = system.bookTicket("Alice", 100, "Second", 3);
        assertTrue(result1.contains("Ticket booked"), "Booking should be successful");

        String result2 = system.bookTicket("Bob", 80, "Sleeper", 0);
        assertEquals("No seats available.", result2, "Should not book if no seats");

        String result3 = system.bookTicket("Eve", -50, "First", 2);
        assertEquals("Ticket booking failed due to invalid input.", result3, "Invalid input should fail");

        String result4 = system.bookTicket("Charlie", 70, "Luxury", 2);
        assertEquals("Ticket booking failed due to invalid input.", result4, "Invalid class should fail");
    }
}

package com.example;

import static org.junit.jupiter.api.Assertions.*;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.CsvSource;

public class TrainTicketingSystemParameterizedTest {

    TrainTicketingSystem system = new TrainTicketingSystem();

    @ParameterizedTest
    @CsvSource({
        "100, First, 150.0",
        "80, Second, 80.0",
        "120, Sleeper, 90.0"
    })
    public void testCalculateFareMultipleInputs(double distance, String classType, double expectedFare) {
        assertEquals(expectedFare, system.calculateFare(distance, classType), 0.001);
    }

    @ParameterizedTest
    @CsvSource({
        "Alice, 100, First, 1, Ticket booked",
        "Bob, 80, Sleeper, 0, No seats available.",
        "Charlie, -50, First, 2, Ticket booking failed due to invalid input.",
        "Eve, 70, Luxury, 2, Ticket booking failed due to invalid input."
    })
    public void testBookTicketParameterized(String name, double distance, String classType, int seats, String expectedPart) {
        String result = system.bookTicket(name, distance, classType, seats);
        assertTrue(result.contains(expectedPart));
    }
}

Software Testing Overview
--------------------------
Software testing is the process of evaluating a software application to identify defects, ensure
quality, and verify that it meets the specified requirements. It involves executing the software
under controlled conditions and checking for expected behaviour and performance.

1. Black Box Testing

What is it?
Black Box Testing is a testing technique where the internal structure or code of the application
is not known to the tester. The focus is on the functionality and behaviour of the software.

Why is it used?
 Ensures the software meets user requirements.
 Detects functional errors without needing knowledge of internal code.
 Suitable for system and acceptance testing.

How is it performed?
 Identify inputs and expected outputs.
 Execute test cases based on functional requirements.
 Compare actual vs. expected results.

Significant Role
 Helps in validating the overall functionality of the system.
 Detects user interface, performance, and usability issues.
 Allows testers without programming knowledge to participate in testing.

Examples:
 Equivalence Partitioning: Dividing input values into valid and invalid groups.
 Boundary Value Analysis: Testing at the edge of input ranges.
 Decision Table Testing: Checking different input combinations and their expected
outputs.

2. White Box Testing
What is it?
White Box Testing (also called Glass Box or Structural Testing) is a technique where the
internal logic, structure, and code of the application are tested. Testers must understand the
internal workings of the software.

Why is it used?
 Helps identify hidden errors in the code structure.
 Ensures efficient code execution and security.
 Used for unit testing and integration testing.

How is it performed?
 Analyze the source code.
 Design test cases to cover paths, loops, and logic conditions.
 Execute tests and check code coverage.

Significant Role
 Helps in improving code efficiency.
 Detects security vulnerabilities.
 Ensures correctness of individual code components.
Examples:
 Statement Coverage: Ensures every line of code is executed at least once.
 Branch Coverage: Tests all decision points (if-else conditions).
 Path Coverage: Verifies all possible execution paths.

3. Why Software Testing?
 Ensures Quality: Helps in delivering a defect-free product.
 Saves Cost & Time: Detecting bugs early reduces development cost and rework.
 Enhances Security: Identifies vulnerabilities before software deployment.
 Improves User Satisfaction: Ensures a seamless user experience.

4. What Should Be Tested?
 Functional requirements (features, user inputs, outputs).
 Non-functional aspects (performance, security, usability).
 Integration of different modules.
 Compatibility across devices and platforms.

5. How Software Testing is Done?
 Requirement Analysis: Understanding the needs.
 Test Planning: Preparing test strategy and cases.
 Test Execution: Running test cases.
 Defect Reporting: Logging and tracking bugs.
 Test Closure: Ensuring issues are fixed and software is ready for release.

Conclusion
 Both Black Box and White Box Testing play a crucial role in software development.
 Black Box Testing ensures the software works as expected.
 White Box Testing validates internal code quality.
 Together, they contribute to building a reliable, high-quality software product.

Integration Testing
--------------------

1. What is Integration Testing?
 Integration Testing is a level of software testing where individual software modules
(usually classes, functions, or components) are combined and tested as a group to ensure
they work together as intended.
 The primary focus is to verify the interaction between different components and ensure
that data flows correctly between them.
2. Why is Integration Testing Needed?
Unit testing focuses on testing individual classes or methods in isolation. However, most
software systems consist of multiple interacting components.
 Real-world software rarely operates in isolation.
 Errors often arise at the boundaries between components.
 Systems fail when data passed between modules is incompatible or mishandled.
Without integration testing, the system may pass unit tests but still fail in the real environment
due to interaction bugs.
3. Significance of Integration Testing
 Ensures seamless interaction between modules.
 Detects missing or incorrect data exchange.
 Reduces risk of late discovery of critical bugs.
 Ensures that combined units meet system requirements.
 Detects interface mismatch errors (data type mismatches, incorrect return values).
 Essential for testing service-oriented architectures (like microservices or layered Java
applications).
4. Prerequisites for Integration Testing
Before starting integration testing, you must ensure:
 Individual modules/classes have passed unit tests.
 Business logic flow is understood.
 Expected interactions between modules are documented.
 All dependent modules are available (real or stubbed).
 Test data is prepared to simulate realistic scenarios.
 Development environment is stable and supports integration test execution.


8. Steps to Perform Integration Testing (General Process)

Step 1 – Identify Modules to Combine
 List all modules, services, or classes to test together.
 Define which classes interact with each other.

Step 2 – Define Test Scenarios
 Identify real-world scenarios requiring multiple modules to interact.
 Examples: Placing an order, processing payment, generating invoice.

Step 3 – Set up Test Data
 Create realistic data that flows across modules.

Step 4 – Execute Tests
 Call methods that trigger multi-class interactions.
 Verify data flow, success/failure handling, error propagation.

Step 5 – Log and Report Issues
 Capture interface errors, missing data, or unexpected behavior.
 Report and resolve issues between teams if necessary.

9. Refer the Example – Integration Testing in Java
Modules
 OrderService calls PaymentService.
 Payment can succeed or fail.
Integration Test Scenario
 Place an order through OrderService.
 Verify if:

o Payment success places order.
o Payment failure cancels order.

Coverage Testing

1. What is Code Coverage Testing?
Code Coverage Testing is a technique used to measure the extent to which source code
is executed during testing. It ensures that test cases cover all possible execution paths.
2. Why is Code Coverage Needed?

 Ensures better software reliability.

 Provides metrics such as line coverage, branch coverage, and method coverage.

Parameterized Testing
----------------------
1. Introduction to Parameterized Testing
Parameterized testing is a technique in software testing where the same test case is executed
multiple times with different sets of input values. This helps improve test coverage, reduces
redundancy, and enhances efficiency in software testing.
2. Benefits of Parameterized Testing
 Reduces code duplication by running the same test with different inputs.
 Improves test coverage by verifying multiple scenarios.
 Enhances maintainability as test logic remains unchanged.
 Helps in edge case testing by easily modifying test inputs.
3. Implementing Parameterized Testing

Best Practices for Parameterized Testing
 Choose meaningful test data that represents real-world scenarios.
 Cover edge cases, including boundary values and invalid inputs.
 Avoid excessive parameterization that makes tests hard to read.
 Use descriptive names for test functions and parameters.

5. Summary
Parameterized testing enhances test efficiency by running the same test logic with different
inputs, improving test coverage, and reducing redundancy. Different testing frameworks such as
pytest, JUnit, NUnit, and Google Test provide built-in support for parameterized tests.
